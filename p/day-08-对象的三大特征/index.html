1 封装

1.1 概述

  • 为什么需要封装？
    • 有些数据赋值的时候语法上是合法的
    • 但是在实际应用中并不行
      • 年龄范围 0~140
      • 结账金额不能为负数
    • 需要人为限制赋值的数据范围

1.2 封装流程

  • 1、私有化属性
  • 2、提供公开的方法
    • setXxx 修改
    • getXxx 获取
  • 3、在方法中添加访问属性的具体规则

public class People {
	// 属性
	String name;
	// 私有化属性--只能在当前类中访问这个属性
	private int age;
	String gender;
	
	public People() {
		super();
	}
	
	public int getAge() {
		return age;
	}
	
	public void setAge(int age) {
		// 检测数据是否合法
		if (age>=0 && age<=140) {
			this.age = age;
		} else {
			this.age = -1;
		}
	}

	@Override
	public String toString() {
		return "People [name=" + name + ", age=" + age + ", gender=" + gender + "]";
	}
	
}

/**
 * 创建学生类
 * 	属性
 * 		姓名
 * 		年龄--需要注意赋值的合法性
 * 		地址
 * 		备注信息
 * 	方法
 * 		展示
 * 
 */
public class Student {
	// 属性
	String name;
	private int age;
	String address;
	String info;

	public Student() {}
	
	// 构造方法也可以私有
	private Student(String name) {
		this.name = name;
	}
	
	public Student(String name, int age, String address, String info) {
		super();
		this.name = name;
		// 防止构造器绕过限制
		this.setAge(age);
		this.address = address;
		this.info = info;
	}

	public int getAge() {
		return age;
	}

	public void setAge(int age) {
		if (age>=0 && age<=140) {
			this.age = age;
		} else {
			System.err.println("您赋值的年龄不合法:" + age);
			this.age = -1;
		}
	}
	
	private void secert() {
		System.out.println("我有很多小秘密,不能告诉你...");
	}

	// 方法
	@Override
	public String toString() {
		return "Student [name=" + name + ", age=" + age + ", address=" + address + ", info=" + info + "]";
	}
}

3 继承

3.1 概述

3.1.1 生活中的继承

  • 从亲属那里获得财、物

3.1.2 程序中的继承

  • class A extends B

    • 类 A 继承类 B
    • A 是子类，B 是父类

  • 子类从父类获取属性和方法

3.2 继承的意义

  • 子类可以使用父类中的属性和方法，提高了代码的复用性
  • 子类中可以定义独有的属性和方法，提高了代码的扩展性

3.3 Java 继承的特点

  • 单继承

    • 一个类只能存在一个直接父类

  • 多级继承

    • 一个类的父类可以继承其他类当做父类
    • 一类在继承 A 类的同时还能被其 C 类继承

  • 在整个继承链中，属性和方法逐级叠加

    • 越靠近下层的类，属性个方法越多
    • 越靠近上层的类，属性和方法概括性越强

4 重写

4.1 概述

  • 重写是指在子类中出现了和父类中名字相同的方法

    • 他们的返回值类型相同
    • 他们的参数列表相同
    • 他们的访问修饰符
      • 子类中的方法修饰符范围要大于等于父类中的方法

  • 简单的理解

    • 子类中方法和父类方法的声明部分完全一样（唯一能改的是修饰符）
    • 方法体不一样

  • 重写的目的是

    • 父类中提供的方法不能满足子类的个性化需求
    • 子类重写书写方法体中的内容

public class FoodFactory {
	
	/**
	 * 	点菜的方法
	 * @param foodNum	菜的编号
	 * @return
	 */
	public Food orderFood(int foodNum) {
		
		Food food = null;
		
		switch (foodNum) {
			case 1:
				food = new LamianNoodles();
				break;
				
			case 2: 
				food = new DongpoPork();
				break;
				
			default:
				food = new Food();
				break;
		}
		return food;
	}
}
