Hello~

CCB 带来了一个全新的迷你 DDNS 工具，帮助佬们快速白嫖部署 DDNS Worker~

它在做什么?

可能有些佬友不知道这是什么工具

它是一个 ddns-go 同款工具，用于解决某些场景下，服务器会定时更新 IP 的问题。

不像传统的服务器，解析 DNS 后就不需要进行管理，因为 IP 是静态的。

那么针对动态 IP，就得使用动态更新的办法~

它和同款工具的优势?

  • 个人感觉较为安全（下文细说）

  • 极简，属于是谁来都能看懂的代码（可快速二次开发自己的个性化版本）

  • 干净，不会出现多余的奇奇怪怪的功能（就修改个 DNS）

  • 单点 CF，有些工具会额外支持其他服务商（出发点很好，但是对于只用 CF 的用户来说，使用它们无疑是增大了自己的心智负担和维护精力）

  • 兼容性强，没有多余的包/多余的环境，只要能跑 shell 脚本，就能用~（哪怕你只剩下了1MB的空间）

  • 内置 TG 通知（因为 API 调用简单）

工具诞生的起源

本来购入了小鸡，因为是动态 IP，所以在想办法使用 DDNS 解决问题。

找到了大家常用的 ddns-go，打开文档—头大，眼花，难绷

然后其他的 ddns 的脚本，会塞入自己的 CloudFlare Api Key

这样会让部分有 密钥洁癖 的佬友感到厌烦 (比如我自己)

鉴于复杂性&洁癖的原因，此工具诞生

（当然最主要是 CCB 有点笨，不会用 ddns-go 之类工具）

怎么安装?

  • 准备工作

  • 申请 Api Key

打开 CF 主界面

点击复制 CF Global Key

创建完成后复制自己的 Token

  • 打开 CF-Worker，点击创建

随便命名后进行部署，然后点击编辑代码

  • 复制项目中 worker.js 的所有代码，粘贴 → 点击部署

  • 返回 Worker 的设置界面

类型选择：Secert（密钥）

CF_API_KEY：刚刚申请的密钥

CF_API_EMAIL：你的账号邮箱

API_SECRET：通信密钥 (主控端和节点端通信鉴权使用)

TG-BOT 配置 (可选):

TG_BOT_TOKEN：Bot 的 Token

TG_CHANNEL_ID(这个可以选 文本 类型)：推送消息的频道 ID

  • 节点端部署

使用 README 中提供的命令，下载后修改配置内的变量，执行脚本后，即可完成部署！

（执行脚本后会自动添加定时任务~）
